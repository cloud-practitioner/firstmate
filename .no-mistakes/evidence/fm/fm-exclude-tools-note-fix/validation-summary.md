# Worker exclusion live validation

Target: `19a80bda053bf171b5eb4b2154ed66c7f987a7b3`; base: `afd6bd5f02aa43fb98fe465281ed9d731e1e258b`.

## Execution boundary

Real Pi CLI 1.1.0 loaded the unmodified extension generated by Firstmate. Runtime scenarios ran from one private, named Herdr lab through `bin/fm-herdr-lab.sh`. MCP tools came from a disposable JSON-RPC stdio server; a local OpenAI-compatible provider fixture supplied deterministic turns. No external account, operator configuration, shared service, or live fleet pane was used.

The extension-generation setup used existing isolated spawn-test dependency fixtures. These generation/unit checks are not labelled live. The subsequent Pi agent loop, registry, MCP connection, codemode execution, tool-call blocking, lifecycle events, persisted status, and declaration consumers were real runtime behavior. Negative exclusion scenarios intentionally omitted Pi's `--exclude-tools` to exercise an actually present listed tool.

Correctly excluded names were absent from `ALL_TOOLS`, `searchTools`, and `describeTool`; direct script calls were unavailable. An unlisted read tool remained callable. In failure-injection runs, listed tools were registered but codemode nested calls were blocked by the generated extension and never reached the MCP server.

Terminal `done:` and `failed:` remained authoritative even when a warning followed them; `fm-crew-state.sh` reported `state: done` and `state: failed`. A concurrent resolver wrote before or after the warning; both decision folds remained closed and warnings remained visible through `scan_unread_surface_lines`.

## Before/after regression proof

The base commit's real spawn-generated extension, loaded by the same Pi fixture, emitted `unmatched exclusion entries (unverified...)` for correctly hidden and unavailable tools. Its no-false-warning assertion failed as expected. The target extension passed the identical correctly-excluded runtime scenario with no warning. See `baseline/correctly-excluded-status.txt` versus `correctly-excluded-status.txt`.

## Targeted deterministic checks

`fm-spawn-dispatch-profile.test.sh` selectors: exclusion launch forwarding; worker-registry reporting; absent/empty lists; unsupported runtime refusal; malformed-entry refusal; server-shape refusal; read-failure refusal. These passed. The registry selector also executed sequential declaration preservation, no-event fallback, ordinary notes, warning deduplication, reconnect/delayed checks, and injected concurrent resolutions at both lifecycle callbacks. No full repository suite or lint/static-analysis command ran.
